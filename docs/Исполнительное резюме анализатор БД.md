# Спецификация компонента DatabaseAnalyzer

## 1. Назначение и роль компонента
Модуль **DatabaseAnalyzer** (`src/Analyzers/Database`) предназначен для статического анализа структуры реляционной базы данных и схемы связей на основе метаданных Entity Framework Core.
Компонент выявляет архитектурные и структурные дефекты схемы (отсутствие первичных ключей, неиндексированные внешние ключи, дублирующиеся индексы, отсутствие навигационных свойств, неявные промежуточные таблицы) без необходимости подключения к работающему серверу СУБД.

Компонент подключается к серверному конвейеру через единый контракт `IAnalyzer` и возвращает список унифицированных замечаний `AnalyzerFinding`.

---

## 2. Архитектура и реальный конвейер анализа

Конвейер получения и анализа метаданных состоит из четырех изолированных компонентов:

```
[AnalyzerContext] (RepositoryPath, CommitHash, ProjectPath?)
       │
       ▼
[IDatabaseProjectResolver] (EfCoreDatabaseProjectResolver)
  - Поиск файлов .csproj, исключение тестовых проектов
  - Обнаружение классов, наследующих DbContext
  - Формирование DatabaseProjectResolution (ContextProjectPath, StartupProjectPath)
       │
       ▼
[IEfCoreModelInspector] (EfCoreModelInspector)
  - Вызов 'dotnet build' для исследуемых проектов
  - Динамическая загрузка сборок во временный контекст
  - Поиск DbContext или IDesignTimeDbContextFactory<T>
  - Извлечение IModel (EF Core Design-Time Metadata)
       │
       ▼
[EfCoreMetadataMapper] (EfCoreMetadataMapper)
  - Преобразование IModel в независимую in-memory модель DatabaseMetadata
  - Извлечение сущностей, ключей, внешних ключей, индексов и skip-навигаций
       │
       ▼
[DatabaseAnalyzer] (IAnalyzer)
  - Прогон правил DB01–DB05 по объекту DatabaseMetadata
  - Формирование списка AnalyzerFinding (Rule, Severity, Message, Recommendation)
```

### Основные классы и интерфейсы конвейера:
1. **`IDatabaseProjectResolver` / `EfCoreDatabaseProjectResolver`:** находит `.csproj` в каталоге репозитория, отфильтровывает тестовые каталоги (`TestResults`, `bin`, `obj`), ищет наследников `DbContext` с помощью регулярного выражения `:\s*(?:global::)?(?:[\w]+\.)*DbContext\b` и определяет контекстный и запускаемый проекты.
2. **`IEfCoreModelInspector` / `EfCoreModelInspector`:** выполняет сборку проектов через CLI, загружает сборку проекта через `Assembly.LoadFrom`, находит тип `DbContext` или фабрику `IDesignTimeDbContextFactory<T>`, инициализирует контекст (например, с SQLite в памяти) и считывает `context.Model`.
3. **`EfCoreMetadataMapper`:** изолирует логику правил от внутренней структуры интерфейсов EF Core. Отображает `IModel` в доменные структуры метаданных:
   - `DatabaseMetadata`: корневой контейнер;
   - `DatabaseEntityMetadata`: имя сущности (`EntityName`), имя таблицы (`TableName`), схема (`Schema`);
   - `DatabaseKeyMetadata`: первичные и альтернативные ключи (`IsPrimaryKey`, `PropertyNames`);
   - `DatabaseForeignKeyMetadata`: внешний ключ, главная сущность (`PrincipalEntityName`), свойства связи (`PropertyNames`), навигация к главной сущности (`NavigationToPrincipal`);
   - `DatabaseIndexMetadata`: имя (`Name`), столбцы (`PropertyNames`), уникальность (`IsUnique`);
   - `DatabaseSkipNavigationMetadata`: связи многие-ко-многим (`NavigationName`, `TargetEntityName`, `JoinEntityTableName`, `IsImplicitJoinEntity`).
4. **`IDatabaseMetadataProvider` / `EfCoreMetadataProvider`:** фасад, объединяющий этапы разрешения проектов, инспекции модели и маппинга.

## 3. Спецификация правил анализа (DB01–DB05)

Все правила реализованы в классе `DatabaseAnalyzer.cs` и подтверждены юнит-тестами.

### DB01: Сущность без первичного ключа
- **Код правила:** `DB01`
- **Уровень критичности:** `Severity.Warning`
- **Назначение:** Обнаружение сущностей модели данных, для которых не определен первичный ключ.
- **Условие срабатывания:** Для сущности `DatabaseEntityMetadata` отсутствует ключ с флагом `IsPrimaryKey == true`:
  ```csharp
  if (!entity.Keys.Any(key => key.IsPrimaryKey))
  ```
- **Текст сообщения:**
  `Сущность '{entity.EntityName}' (таблица '{entity.TableName}') не имеет первичного ключа.`
- **Рекомендация:**
  `Проверьте, что сущность намеренно настроена без первичного ключа. Для таблицы с изменяемыми данными задайте первичный ключ; для представления или проекции убедитесь, что отсутствие ключа предусмотрено.`
- **Ограничения:** В EF Core сущности без ключа (`Keyless Entity Types`) допустимы для маппинга SQL-представлений (Views) или выполнения не отслеживаемых запросов, поэтому уровень критичности задан как `Warning`, а не `Critical`.
- **Тесты:** `DatabaseAnalyzerTests.AnalyzeAsync_EntityWithoutPrimaryKey_ReturnsWarning`, `DatabaseAnalyzerTests.AnalyzeAsync_EntityWithPrimaryKey_DoesNotReturnWarning`.

---

### DB02: Внешний ключ без навигационного свойства к главной сущности
- **Код правила:** `DB02`
- **Уровень критичности:** `Severity.Warning`
- **Назначение:** Проверка соблюдения проектных соглашений по навигационным свойствам связей.
- **Условие срабатывания:** Внешний ключ сущности не имеет навигационного свойства, ссылающегося на главную сущность (`string.IsNullOrWhiteSpace(foreignKey.NavigationToPrincipal)`):
  ```csharp
  if (string.IsNullOrWhiteSpace(foreignKey.NavigationToPrincipal))
  ```
- **Текст сообщения:**
  `Рекомендация: внешний ключ '{foreignKey.Name}' сущности '{entity.EntityName}' не имеет навигационного свойства к главной сущности '{foreignKey.PrincipalEntityName}'. Это допустимо в EF Core, но не соответствует рекомендуемому проектному соглашению.`
- **Рекомендация:**
  `В рамках проектного соглашения рекомендуется добавить навигационное свойство в сущность '{entity.EntityName}' для внешнего ключа '{foreignKey.Name}'. Это обеспечивает типобезопасный доступ к связанной сущности '{foreignKey.PrincipalEntityName}' и поддержку удобной загрузки связанных данных через LINQ (.Include()). Это является рекомендацией по стилю моделирования и не нарушает целостность БД или требования EF Core.`
- **Ограничения:** EF Core допускает теневые внешние ключи (shadow FK) без навигационных свойств в C# классах. Данное правило является проверкой соглашений команды разработки.
- **Тесты:** `DatabaseAnalyzerTests.AnalyzeAsync_ForeignKeyWithoutNavigation_ReturnsWarning`, `DatabaseAnalyzerTests.AnalyzeAsync_ForeignKeyWithNavigation_DoesNotReturnWarning`.

---

### DB03: Неявная связь многие-ко-многим через скрытую промежуточную таблицу
- **Код правила:** `DB03`
- **Уровень критичности:** `Severity.Info`
- **Назначение:** Выявление связей many-to-many, сконфигурированных без явного объявления связующей доменной сущности (join entity).
- **Условие срабатывания:** Наличие skip-навигации (`SkipNavigations`), для которой флаг `IsImplicitJoinEntity` равен `true`. Применяется стабильная дедупликация (замечание регистрируется один раз для сущности с лексикографически меньшим именем):
  ```csharp
  if (skipNav.IsImplicitJoinEntity)
  ```
- **Текст сообщения:**
  `Рекомендация: связь многие-ко-многим между сущностями '{entity.EntityName}' и '{skipNav.TargetEntityName}' настроена через неявную промежуточную таблицу '{skipNav.JoinEntityTableName}'.`
- **Рекомендация:**
  `Рассмотрите возможность создания явной связующей сущности (join entity) для таблицы '{skipNav.JoinEntityTableName}'. Это позволит явно управлять схемой связующей таблицы, индексами и добавлять дополнительные атрибуты связи (например, дату создания или статус) без изменения типа связи в будущем. Использование неявной связи допустимо в EF Core и является рекомендацией по проектированию модели.`
- **Ограничения:** Правило анализирует исключительно связи, где промежуточная таблица не имеет явного класса сущности в C# коде. Если связующая сущность объявлена явно (например, `class OrderItem { int OrderId; int ProductId; }`), правило не срабатывает.
- **Тесты:** `DatabaseAnalyzerTests.AnalyzeAsync_ImplicitManyToMany_ReturnsInfo`, `DatabaseAnalyzerTests.AnalyzeAsync_ExplicitManyToMany_DoesNotReturnInfo`.

### DB04: Внешний ключ без подходящего индекса
- **Код правила:** `DB04`
- **Уровень критичности:** `Severity.Warning`
- **Назначение:** Предотвращение деградации производительности операций JOIN, фильтрации и каскадного удаления из-за отсутствия индексов на столбцах внешних ключей.
- **Условие срабатывания:** Столбцы внешнего ключа не покрываются ни одним индексом сущности (индекс должен содержать столбцы FK в качестве лидирующего префикса в том же порядке):
  ```csharp
  var hasMatchingIndex = entity.Indexes.Any(index =>
      index.PropertyNames.Count >= foreignKeyProperties.Count &&
      index.PropertyNames.Take(foreignKeyProperties.Count).SequenceEqual(foreignKeyProperties, StringComparer.Ordinal));
  ```
- **Текст сообщения:**
  `Внешний ключ '{foreignKey.Name}' сущности '{entity.EntityName}' не имеет подходящего индекса по столбцам: {string.Join(", ", foreignKeyProperties)}.`
- **Рекомендация:**
  `Проверьте частоту соединений и фильтрации по столбцам внешнего ключа. При необходимости добавьте индекс, начинающийся со столбцов внешнего ключа в указанном порядке.`
- **Ограничения:** Анализируются индексы, зафиксированные в модели EF Core (`[Index]`, `builder.HasIndex()`). Индексы, созданные вручную в СУБД вне миграций EF Core, не учитываются.
- **Тесты:** `DatabaseAnalyzerTests.AnalyzeAsync_ForeignKeyWithoutIndex_ReturnsWarning`, `DatabaseAnalyzerTests.AnalyzeAsync_ForeignKeyWithCoveringIndex_DoesNotReturnWarning`.

---

### DB05: Дублирующиеся индексы
- **Код правила:** `DB05`
- **Уровень критичности:** `Severity.Info`
- **Назначение:** Обнаружение избыточных индексов, замедляющих операции вставки/обновления (INSERT/UPDATE/DELETE) и расходующих дисковое пространство.
- **Условие срабатывания:** Наличие двух индексов на одной сущности с идентичным набором столбцов и одинаковым признаком уникальности (`IsUnique`):
  ```csharp
  if (firstIndex.IsUnique == secondIndex.IsUnique &&
      firstIndex.PropertyNames.SequenceEqual(secondIndex.PropertyNames, StringComparer.Ordinal))
  ```
- **Текст сообщения:**
  `Индексы '{firstIndex.Name}' и '{secondIndex.Name}' сущности '{entity.EntityName}' дублируются по столбцам: {string.Join(", ", firstIndex.PropertyNames)}.`
- **Рекомендация:**
  `Проверьте необходимость обоих индексов. Если они не отличаются по назначению или параметрам, рассмотрите удаление одного из них.`
- **Ограничения:** Сравниваются только полные совпадения столбцов; частичные перекрытия префиксов индексов в текущей версии не анализируются.
- **Тесты:** `DatabaseAnalyzerTests.AnalyzeAsync_DuplicateIndexes_ReturnsInfo`, `DatabaseAnalyzerTests.AnalyzeAsync_DifferentIndexes_DoesNotReturnInfo`.

## 4. Ограничения и нормализация базы данных

1. **Нормализация 2НФ и 3НФ:**
   Анализ метаданных EF Core **не может служить строгим математическим доказательством** соблюдения второй и третьей нормальных форм. Вторая и третья нормальные формы определяются функциональными зависимостями реального мира между атрибутами ($X \rightarrow Y$), которые не выражаются типами данных C# и не сохраняются в реляционной схеме без дополнительной семантики предметной области.
   `DatabaseAnalyzer` выполняет эвристический структурный аудит:
   - гарантирует наличие суррогатных/естественных первичных ключей (`DB01`);
   - контролирует ссылочную целостность и связность внешних ключей (`DB02`);
   - обеспечивает эффективную индексацию соединений (`DB04`).
2. **Требования к анализируемому проекту:**
   - Проект должен быть написан на .NET / C# и использовать EF Core 8+.
   - Проект должен успешно компилироваться при вызове `dotnet build`.
   - В проекте должен присутствовать класс, наследующий `DbContext`, или реализация `IDesignTimeDbContextFactory<T>`.

## 5. Тестовое покрытие
Модуль `DatabaseAnalyzer` полностью покрыт автоматизированными тестами xUnit в проекте `tests/DatabaseAnalyzer.Tests` (всего 59 тестов):
- `DatabaseAnalyzerTests`: 10 тестов позитивных и негативных сценариев для правил `DB01`–`DB05`.
- `EfCoreMetadataMapperTests`: 15 тестов корректности маппинга сущностей, ключей, навигаций и индексов.
- `EfCoreDatabaseProjectResolverTests`: 12 тестов обнаружения проектов и фильтрации тестов.
- `EfCoreModelInspectorTests`: 8 тестов загрузки сборок и извлечения `IModel`.
- `EfCoreMetadataProviderTests` и `EfCoreMetadataProviderModelTests`: 14 интеграционных тестов провайдера.
