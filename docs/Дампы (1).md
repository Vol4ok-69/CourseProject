# Руководство по утилите ProjectTreeCli (treeq)

У меня есть моя самописная программа для создания дампов. Вот ее актуальное описание (`treeq -h`):

```text
Description:
  Project tree viewer

Использование:
  ProjectTreeCli [options]

Параметры:
  -d, --depth <depth>                    Tree depth [default: 10]
  -e, --exclude <exclude>                Excluded folders/files
  -o, --only <only>                      Only extensions
  -c, --content                          Show file content
  -out, --output <output>                Output file path
  -f, --format <format>                  Export format [default: tree]
  -mfs, --max-file-size <max-file-size>  Maximum file size in KB [default: 1024]
  -s, --size                             Show file and directory sizes
  --summary                              Show project summary
  --clipboard                            Copy output to clipboard
  --safe                                 Safe mode (ignore hidden files and secrets)
  -r, --references                       Show project-to-project references
  -p, --packages                         Show NuGet packages
  --include <include>                    Include only specified files/directories/globs
  --files-from <files-from>              Read included paths from a text file
  --exclude-pattern <exclude-pattern>    Excluded glob patterns
  --line-numbers                         Add line numbers to file content
  --code-only                            Only export code files, excluding documentation and binary docs
  --git-content                          Export content of changed files from Git
  -?, -h, --help                         Show help and usage information
  --version                              Показать информацию о версии
```

---

## 1. Подробное описание и способы применения каждого флага

### `-d`, `--depth <depth>` (Глубина дерева)
- **Назначение**: Ограничивает глубину рекурсивного обхода каталогов.
- **Значение по умолчанию**: `10`.
- **Примеры**:
  ```powershell
  treeq -d 2
  treeq --depth 1 -out structure_root.md
  ```
- **Особенности**: Позволяет быстро оценить структуру верхнего уровня без перегрузки выводом глубоких подпапок.

---

### `-e`, `--exclude <exclude>` (Исключение папок и файлов)
- **Назначение**: Исключает указанные имена файлов или папок из сканирования.
- **Поддержка нескольких значений**: Через пробел или точку с запятой `;`.
- **Примеры**:
  ```powershell
  treeq -e "tests" "bin" "obj"
  treeq -c -e "README.md;temp.log" -out dump.md
  ```
- **Особенности**: Исключённые папки не сканируются рекурсивно, а исключённые файлы полностью исчезают из дерева и содержимого.

---

### `-o`, `--only <only>` (Фильтрация по расширениям)
- **Назначение**: Оставляет в дереве и содержимом только файлы с указанными расширениями.
- **Примеры**:
  ```powershell
  treeq -o ".cs" ".csproj" ".slnx"
  treeq -c -o ".cs" -out source_dump.md
  ```
- **Особенности**: Обязательно указывать точку в начале расширения (`.cs`, а не `cs`).

---

### `-c`, `--content` (Выгрузка содержимого файлов)
- **Назначение**: Выгружает содержимое файлов проекта в секцию `# File Contents`.
- **Формат по умолчанию**: Если формат явно не задан (`tree`), флаг `-c` автоматически переключает экспорт на `markdown`.
- **Примеры**:
  ```powershell
  treeq -c -out project_dump.md
  treeq -c --line-numbers -out source_review.md
  ```
- **Особенности**: Применяет подсветку синтаксиса Markdown для большинства известных языков программирования (C#, Python, JS/TS, SQL, JSON, XML и др.). Для таблиц `.csv` и `.xlsx` строит аккуратные Markdown-таблицы. Бинарные файлы не выгружаются.

---

### `-out`, `--output <output>` (Путь к файлу вывода)
- **Назначение**: Перенаправляет результат работы в файл в кодировке UTF-8 вместо стандартного вывода консоли.
- **Примеры**:
  ```powershell
  treeq -out structure.md
  treeq -c -out dump.md
  ```
- **Особенности**: Сам файл вывода автоматически добавляется в список исключений, чтобы не попадать в дерево собственного дампа.
- **Использование в CourseProject**: В репозитории курсового проекта сохранять все файлы, созданные treeq, в директорию dumps/. Пример:
	```powershell
	PS C:\Users\ivank\Desktop\Uceba\Projects\CourseProject> treeq --git-content --safe --line-numbers -out dumps/review_td003_current.md
	PS C:\Users\ivank\Desktop\Uceba\Projects\CourseProject> treeq -c --safe --line-numbers --include "src/Backend;src/Analyzers/Database/Runner;tests/Backend.Tests" -out dumps/source_td003_current.md
	```

---

### `-f`, `--format <format>` (Формат экспорта)
- **Назначение**: Задаёт формат вывода структуры проекта.
- **Поддерживаемые форматы**:
  - `tree` (по умолчанию для чистого дерева) — ASCII-дерево;
  - `markdown` (автоматически при `-c`, `--git-content`, `-r`, `-p`) — разметка Markdown;
  - `json` — структурированный JSON с узлами каталогов и файлов;
  - `xml` — сериализованный XML структуры проекта;
  - `yaml` — структурированный YAML.
- **Примеры**:
  ```powershell
  treeq -f json -out structure.json
  treeq -f yaml
  ```
- **Особенности**: Секция содержимого файлов (`File Contents`), Git Changes, References и Packages поддерживаются форматом `markdown`.

---

### `-mfs`, `--max-file-size <max-file-size>` (Лимит размера файла в KB)
- **Назначение**: Ограничивает чтение и экспорт содержимого файлов, превышающих лимит.
- **Значение по умолчанию**: `1024` (1024 KB = 1 MB).
- **Правило поведения**:
  - **Файл обязательно остаётся в дереве проекта** (в структуре виден его реальный размер при флаге `-s`).
  - Содержимое файла **не загружается в память**.
  - Вместо содержимого выводится сообщение:
    ```text
    [Содержимое не выведено: размер файла превышает установленный лимит --max-file-size (1024 KB)]
    ```
- **Примеры**:
  ```powershell
  treeq -c -mfs 2048 -out dump.md
  treeq -c -mfs 100 -out source_dump.md
  ```
- **Граничные условия**:
  - Если размер файла **точно равен** `MaxFileSizeKb * 1024` байт, содержимое выводится.
  - Если размер файла строго больше лимита — вывод содержимого блокируется.
  - Отрицательные значения (`-mfs -10`) запрещены и возвращают ошибку валидации.

---

### `-s`, `--size` (Отображение размеров)
- **Назначение**: Показывает размеры файлов и папок в человекочитаемом виде (`B`, `KB`, `MB`, `GB`).
- **Примеры**:
  ```powershell
  treeq -s
  treeq -s -out structure_sizes.md
  ```

---

### `--summary` (Сводка по проекту)
- **Назначение**: Формирует сводную аналитику в конце вывода: общее число файлов, папок, общий размер и распределение по расширениям.
- **Примеры**:
  ```powershell
  treeq --summary
  treeq -c --summary -out dump_with_summary.md
  ```

---

### `--clipboard` (Копирование в буфер обмена)
- **Назначение**: Копирует сгенерированный результат в буфер обмена ОС (работает асинхронно).
- **Примеры**:
  ```powershell
  treeq -c --clipboard
  treeq --safe --git-content --clipboard
  ```

---

### `--safe` (Единый безопасный режим)
- **Назначение**: Безопасный экспорт проекта для анализа и передачи в LLM без риска утечки учётных данных и приватных ключей.
- **Что исключает**:
  1. **Скрытые файлы и папки**: файлы и папки, начинающиеся с точки (`.git`, `.vscode`, `.idea`), и объекты с атрибутом `FileAttributes.Hidden` (Windows).
  2. **Файлы окружения**: `.env`, `.env.local`, `.env.production` и любые `.env.*`.
     - *Исключение*: разрешённые шаблоны конфигураций (`.env.example`, `.env.sample`, `.env.template`, `.env.dist`) остаются видимыми.
  3. **Файлы приватных ключей и хранилищ**: `id_rsa`, `id_ed25519`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.secret`, `secrets.*`, `credentials.json`.
  4. **Секреты внутри содержимого файлов** (через встроенный `SecretDetector`):
     - Приватные PEM-ключи (`BEGIN RSA PRIVATE KEY`, `BEGIN OPENSSH PRIVATE KEY` и т.д.);
     - Токены API (GitHub PAT, Slack, AWS keys, GitLab, Stripe, OpenAI `sk-`);
     - Пароли и секретные ключи в файлах конфигураций (`password = ...`, `"api_key": "..."`);
     - Безопасные плейсхолдеры (`YOUR_API_KEY`, `change_me`, `example`, `placeholder`, `dummy`) и обычные имена переменных в коде ложных срабатываний не вызывают.
- **Примеры**:
  ```powershell
  treeq --safe -out safe_structure.md
  treeq -c --safe -out safe_dump.md
  ```
- **Абсолютный приоритет**: Файлы, исключённые режимом `--safe`, невозможно раскрыть через `--include`, `--files-from` или `--git-content`. Если файл заблокирован или не может быть проверен, он безопасно исключается.

---

### `--code-only` (Только исходный код)
- **Назначение**: Сохраняет полное дерево проекта, но отфильтровывает содержимое документации, заметок, офисных документов и лицензий из секции выгрузки.
- **Правило поведения**:
  - Файлы **остаются видимыми в дереве проекта**.
  - Содержимое **не выгружается** для:
    - Расширений: `.md`, `.txt`, `.docx`, `.xlsx`, `.csv`, `.drawio`.
    - Имен файлов: `LICENSE`, `.env`.
    - Любых файлов из каталогов `docs/` на любой глубине (`docs/`, `server/docs/`, `client/docs/`).
- **Примеры**:
  ```powershell
  treeq -c --code-only -out code_dump.md
  treeq --git-content --code-only -out review_dump.md
  ```
- **Особенности**: Исходный код (`.cs`, `.py`, `.ts`, `.json`, `.xml`, `.sql` и т.д.) выгружается полностью.

---

### `--git-content` (Выгрузка изменений Git)
- **Назначение**: Строит полное дерево проекта, но содержимое выгружает **только для файлов, изменённых в Git**.
- **Порядок секций в Markdown**:
  1. `# Project Structure` — полное дерево текущего проекта.
  2. `# Project References` (если задан `-r`).
  3. `# NuGet Packages` (если задан `-p`).
  4. `# Git Changes` — таблица изменений Git со статусами (`modified`, `new file`, `untracked`, `deleted`, `renamed`, `copied`, `type changed`, `conflicted`).
  5. `# File Contents` — заголовки вида `## [status] relative/path` и содержимое только изменённых файлов.
- **Примеры**:
  ```powershell
  treeq --git-content -out review_git.md
  treeq --git-content --code-only -out review_code_git.md
  treeq --git-content --safe -out review_safe_git.md
  ```
- **Особенности**:
  - Статусы получаются через `git status --porcelain=v1 -z` в бинарном режиме, что исключает ошибки при пробелах и кириллице в путях.
  - Удалённые файлы отображаются в таблице со статусом `deleted`, но пустое содержимое для них не выводится.
  - Переименования отображаются со статусом `renamed` и указанием старого пути (`Previous Path`) только тогда, когда сам Git определяет `R`.
  - Запуск во вложенном каталоге отбирает только изменения, относящиеся к текущей подпапке.
  - Запуск вне Git-репозитория возвращает понятную ошибку и ненулевой код возврата.

---

### `-r`, `--references` (Ссылки между проектами)
- **Назначение**: Анализирует решения и проекты `.csproj`, `.fsproj`, `.vbproj` и выводит секцию `# Project References` со списком зависимостей между проектами.
- **Примеры**:
  ```powershell
  treeq -r -out project_references.md
  treeq -c -r -out dump_references.md
  ```

---

### `-p`, `--packages` (NuGet-пакеты)
- **Назначение**: Выводит секцию `# NuGet Packages` с перечнем используемых библиотек и версий (`Requested` и `Resolved`).
- **Поддержка**: Поддерживает современный SDK-style формат через `dotnet list package --format json` и устаревший `packages.config`.
- **Примеры**:
  ```powershell
  treeq -p -out packages_dump.md
  treeq -r -p -out project_references_packages.md
  ```

---

### `--include <include>` (Точечное включение путей и glob-шаблонов)
- **Назначение**: Оставляет в дереве и содержимом только указанные файлы, папки или glob-шаблоны.
- **Поддержка разделителей**: Несколько аргументов через пробел или точку с запятой `;`.
- **Примеры**:
  ```powershell
  treeq -c --include "src/Backend;src/Shared" -out source_dump.md
  treeq -c --include "**/*.cs;**/*.json" -out code_dump.md
  ```

---

### `--files-from <files-from>` (Список путей из текстового файла)
- **Назначение**: Считывает список путей и glob-шаблонов для включения из текстового файла (пустые строки и строки с комментариями `#` игнорируются).
- **Примеры**:
  ```powershell
  treeq -c --files-from "files.txt" -out source_dump.md
  ```

---

### `--exclude-pattern <exclude-pattern>` (Glob-шаблоны исключений)
- **Назначение**: Исключает пути по glob-шаблонам (например, `**/bin/**`, `**/obj/**`, `**/*.tmp`).
- **Примеры**:
  ```powershell
  treeq -c --include "src" --exclude-pattern "**/bin/**" "**/obj/**" -out source_dump.md
  ```

---

### `--line-numbers` (Нумерация строк)
- **Назначение**: Добавляет номера строк в блоки кода выгружаемого содержимого файлов (`   1 | ...`).
- **Ограничение**: Требует активации режима выгрузки содержимого (`-c` или `--git-content`). Запуск `--line-numbers` без них вернёт ошибку: `Error: --line-numbers requires --content.`
- **Примеры**:
  ```powershell
  treeq -c --line-numbers -out review_dump.md
  treeq --git-content --line-numbers -out review_git.md
  ```

---

## 2. Матрица поведения и разрешение конфликтов параметров

| Комбинация флагов | Приоритет / Поведение | Что происходит |
|---|---|---|
| `-c` + `--git-content` | **Приоритет у `-c`** | Полный дамп всего проекта. Выгружается содержимое всех файлов проекта, как при обычном `-c`. Таблица `# Git Changes` не создаётся. Ошибки несовместимости нет. |
| `--git-content` + `--code-only` | **Раздельная обработка** | В таблице `# Git Changes` отображаются **все** изменённые файлы (включая `.docx`, `.md`). В секции `# File Contents` выводится содержимое **только** файлов исходного кода. |
| `--safe` + Любой флаг (`--include`, `--files-from`, `--git-content`) | **Абсолютный приоритет у `--safe`** | Скрытые файлы, `.env` и файлы с секретами **полностью исключаются** из дерева, из содержимого и из таблицы `# Git Changes`. Обойти безопасность через `--include` невозможно. |
| `--code-only` + Дерево проекта | **Только фильтрация содержимого** | Документы (`.md`, `.docx`, папки `docs/`) остаются в дереве `Project Structure`, но их текст не попадает в `File Contents`. |
| `--exclude` / `--exclude-pattern` + `--include` | **Приоритет у исключений** | Если файл попал под `--include`, но совпал с правилом `--exclude` или `--exclude-pattern`, он исключается. |
| `--max-file-size` + Дерево / Git | **Разделение дерева и содержимого** | Файл, превышающий лимит, сохраняется в дереве проекта и в таблице `# Git Changes`. Вместо содержимого выводится уведомление с указанием лимита. |
| `--line-numbers` без `-c` и без `--git-content` | **Ошибка валидации** | Выводится сообщение: `Error: --line-numbers requires --content.` Код возврата `1`. |
| `-mfs < 0` | **Ошибка валидации** | Выводится сообщение: `Error: --max-file-size must be non-negative.` Код возврата `1`. |
| Запуск `--git-content` вне Git-репозитория | **Ошибка Git** | Выводится понятное сообщение об ошибке в консоль. Код возврата `1`. |

## 3. Примеры практического использования

### Быстрый аудит архитектуры и зависимостей (без содержимого)
```powershell
treeq -r -p -out project_references_packages.md
```

### Безопасный дамп кодовой базы для анализа нейросетью (LLM)
```powershell
treeq -c --safe --code-only -out safe_source_dump.md
```

### Ревью последних изменений Git с нумерацией строк
```powershell
treeq --git-content --code-only --safe --line-numbers -out review_git.md
```

### Точечный дамп конкретных подсистем
```powershell
treeq -c --include "src/Analyzers/Database;tests/DatabaseAnalyzer.Tests;src/Backend/Domain" --exclude-pattern "**/bin/**" "**/obj/**" --line-numbers -out db_analyzer_source.md
```

### Полный производственный дамп со ссылками и пакетами
```powershell
treeq -c --safe --code-only --max-file-size 1024 -r -p -out project_dump.md
```

---

## 4. Следование .gitignore 

Утилита считывает настройки файла .gitignore и не показывает эти файлы в дереве и `-c`, так что не обязательно использовать `--exclude-pattern "**/bin/**" "**/obj/**"` для репозитория CourseProject.

---

## 4. Ограничения .gitignore для файлов дампов

Если требуется дамп, то говори в какой директории и какую команду treeq запускать.
Главное правило:
Если ты говоришь мне команду для вывода, то имя файла вывода должно подходить под ограничения .gitignore:
```
dump*.md
*dump.md
*structure.md
structure*.md
packages*.md
*packages.md
references*.md
*references.md
source*.md
*source.md
review*.md
*review.md
```
