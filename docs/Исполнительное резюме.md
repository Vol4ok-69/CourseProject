# Исполнительное резюме  
Для данного курсового проекта оптимально использовать многослойную архитектуру: отдельные проекты Domain, Application, Infrastructure и API. Сущности доменной модели (пользователи, проекты, коммиты, анализы и результаты анализа) хранятся в PostgreSQL через Entity Framework Core. Техническая часть состоит из ASP.NET Core Web API, которое обрабатывает HTTP-запросы клиентов и запускает анализ в фоне (с помощью `BackgroundService`). Анализаторы (C#, база данных, SQL, безопасность) подключаются через общий интерфейс `IAnalyzer` и возвращают результаты, связанные с конкретным анализом (issues с указанием файла, строки, правила, сообщения и уровня серьезности). Используются JWT-аутентификация для API и Docker Compose для деплоя.

# Нормализованные таблицы PostgreSQL (3НФ)  

```sql
CREATE TABLE "Role" (
    "RoleId"   SERIAL PRIMARY KEY,
    "Name"     TEXT NOT NULL UNIQUE
);

CREATE TABLE "User" (
    "UserId"       SERIAL PRIMARY KEY,
    "Username"     TEXT NOT NULL UNIQUE,
    "PasswordHash" TEXT NOT NULL,
    "RoleId"       INT NOT NULL,
    FOREIGN KEY ("RoleId") REFERENCES "Role" ("RoleId")
);

CREATE TABLE "Project" (
    "ProjectId"  SERIAL PRIMARY KEY,
    "Name"       TEXT NOT NULL,
    "RepoUrl"    TEXT NOT NULL,
    "OwnerId"    INT NOT NULL,
    FOREIGN KEY ("OwnerId") REFERENCES "User"("UserId")
);
-- Добавим уникальный индекс на сочетание (OwnerId, Name) или хотя бы на Name
CREATE UNIQUE INDEX "IX_Project_Owner_Name" ON "Project"("OwnerId", "Name");

CREATE TABLE "Commit" (
    "CommitId"    SERIAL PRIMARY KEY,
    "ProjectId"   INT NOT NULL,
    "CommitHash"  TEXT NOT NULL,
    "CommitDate"  TIMESTAMPTZ NOT NULL,
    FOREIGN KEY ("ProjectId") REFERENCES "Project"("ProjectId")
);
-- Гарантировать уникальность коммита в проекте
CREATE UNIQUE INDEX "IX_Commit_Project_CommitHash" ON "Commit"("ProjectId", "CommitHash");

CREATE TABLE "Analysis" (
    "AnalysisId"   SERIAL PRIMARY KEY,
    "CommitId"     INT NOT NULL,
    "Status"       TEXT NOT NULL,
    "StartedAt"    TIMESTAMPTZ NOT NULL,
    "CompletedAt"  TIMESTAMPTZ NULL,
    FOREIGN KEY ("CommitId") REFERENCES "Commit"("CommitId")
);
-- Индекс по коммиту для быстрого поиска анализов
CREATE INDEX "IX_Analysis_CommitId" ON "Analysis"("CommitId");

CREATE TABLE "AnalysisResult" (
    "ResultId"       SERIAL PRIMARY KEY,
    "AnalysisId"     INT NOT NULL,
    "FilePath"       TEXT NOT NULL,
    "LineNumber"     INT NOT NULL,
    "Rule"           TEXT NOT NULL,
    "Message"        TEXT NOT NULL,
    "Severity"       TEXT NOT NULL,
    "Recommendation" TEXT NULL,
    "AnalyzerType"   TEXT NOT NULL,
    FOREIGN KEY ("AnalysisId") REFERENCES "Analysis"("AnalysisId")
);
-- Индекс по анализу для выборки результатов
CREATE INDEX "IX_AnalysisResult_AnalysisId" ON "AnalysisResult"("AnalysisId");
```

- **Первичные ключи** в каждой таблице – поля вида `*Id` с `SERIAL PRIMARY KEY`.  
- **Внешние ключи**: `User.RoleId → Role.RoleId`, `Project.OwnerId → User.UserId`, `Commit.ProjectId → Project.ProjectId`, `Analysis.CommitId → Commit.CommitId`, `AnalysisResult.AnalysisId → Analysis.AnalysisId`. Это обеспечивает ссылочную целостность.  
- **Индексы и уникальности**: столбцы `Username`, `Role.Name` должны быть уникальны. Добавлены уникальные индексы на сочетания (`OwnerId`, `Name`) в Project и (`ProjectId`, `CommitHash`) в Commit, чтобы избежать дублирования. Индексы по внешним ключам (`CommitId`, `AnalysisId`) ускоряют JOIN-ы.  

# Перечисления (Enums)  
- **AnalysisStatus**: `{ Pending, Running, Completed, Failed }` – статус выполнения анализа.  
- **IssueSeverity**: `{ Low, Medium, High, Critical }` – степень серьёзности найденного нарушения (можно использовать аналогии с Info/Warning/Error, здесь — упрощённые уровни).  
- **AnalyzerType**: `{ CSharp, Database, SQL, Security }` – тип анализатора.  
- **UserRole** (опционально): `{ Admin, User }` – роль пользователя, если не создавать отдельную таблицу Role.  

# Ограничения и индексы (рациональное обоснование)  
- **Ссылочная целостность** – основные и внешние ключи гарантируют непротиворечивость данных (открытые связи между сущностями).  
- **Уникальность** (UNIQUE) на логине пользователя (`Username`) и на комбинациях (`OwnerId`, `Project Name`) исключают дублирование проектов у одного пользователя.  
- **Индексы** по внешним ключам (`CommitId` в Analysis, `AnalysisId` в Results) ускорят выборку связанных данных. Также уникальные индексы на коммитах и проектах предотвращают дублирование и улучшают поиск.  

# DbContext и конфигурация EF Core (Fluent API)  

```csharp
public class AppDbContext : DbContext
{
    public DbSet<Role> Roles { get; set; }
    public DbSet<User> Users { get; set; }
    public DbSet<Project> Projects { get; set; }
    public DbSet<Commit> Commits { get; set; }
    public DbSet<Analysis> Analyses { get; set; }
    public DbSet<AnalysisResult> AnalysisResults { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // User entity
        modelBuilder.Entity<User>(entity =>
        {
            entity.HasKey(e => e.UserId);
            entity.HasIndex(e => e.Username).IsUnique();
            entity.Property(e => e.Username).IsRequired();
            entity.Property(e => e.PasswordHash).IsRequired();
            entity.HasOne<Role>()
                  .WithMany()
                  .HasForeignKey(e => e.RoleId)
                  .OnDelete(DeleteBehavior.Restrict);
        });

        // Role entity
        modelBuilder.Entity<Role>(entity =>
        {
            entity.HasKey(e => e.RoleId);
            entity.Property(e => e.Name).IsRequired();
        });

        // Project entity
        modelBuilder.Entity<Project>(entity =>
        {
            entity.HasKey(e => e.ProjectId);
            entity.Property(e => e.Name).IsRequired();
            entity.Property(e => e.RepoUrl).IsRequired();
            entity.HasIndex(e => new { e.OwnerId, e.Name }).IsUnique();
            entity.HasOne<User>()
                  .WithMany()
                  .HasForeignKey(e => e.OwnerId)
                  .OnDelete(DeleteBehavior.Cascade);
        });

        // Commit entity
        modelBuilder.Entity<Commit>(entity =>
        {
            entity.HasKey(e => e.CommitId);
            entity.Property(e => e.CommitHash).IsRequired();
            entity.Property(e => e.CommitDate).IsRequired();
            entity.HasIndex(e => new { e.ProjectId, e.CommitHash }).IsUnique();
            entity.HasOne<Project>()
                  .WithMany()
                  .HasForeignKey(e => e.ProjectId)
                  .OnDelete(DeleteBehavior.Cascade);
        });

        // Analysis entity
        modelBuilder.Entity<Analysis>(entity =>
        {
            entity.HasKey(e => e.AnalysisId);
            entity.Property(e => e.Status).IsRequired();
            entity.Property(e => e.StartedAt).IsRequired();
            entity.HasOne<Commit>()
                  .WithMany()
                  .HasForeignKey(e => e.CommitId)
                  .OnDelete(DeleteBehavior.Cascade);
        });

        // AnalysisResult entity
        modelBuilder.Entity<AnalysisResult>(entity =>
        {
            entity.HasKey(e => e.ResultId);
            entity.Property(e => e.FilePath).IsRequired();
            entity.Property(e => e.LineNumber).IsRequired();
            entity.Property(e => e.Rule).IsRequired();
            entity.Property(e => e.Message).IsRequired();
            entity.Property(e => e.Severity).IsRequired();
            entity.Property(e => e.AnalyzerType).IsRequired();
            entity.HasOne<Analysis>()
                  .WithMany()
                  .HasForeignKey(e => e.AnalysisId)
                  .OnDelete(DeleteBehavior.Cascade);
        });
    }
}
```  

# API-контракты (минимальные DTO и маршруты)  
- **POST /api/projects** – создание проекта.  
  - *Request Body (JSON)*: `{ "name": "MyProject", "repoUrl": "https://github.com/..." }`.  
  - *Response*: `201 Created`, `{ "projectId": 1, "name": "MyProject", "repoUrl": "...", "ownerId": 5 }` (ProjectDto).  

- **POST /api/projects/{projectId}/analyses** – запустить анализ последнего коммита проекта.  
  - *Request*: пустое тело.  
  - *Response*: `202 Accepted`, `{ "analysisId": 10, "status": "Pending", "startedAt": "2026-09-11T12:00:00Z" }` (AnalysisDto).  

- **GET /api/analyses/{analysisId}** – получить статус анализа.  
  - *Response*: `{ "analysisId": 10, "status": "Completed", "startedAt": "...", "completedAt": "..." }`.  

- **GET /api/analyses/{analysisId}/results** – получить найденные нарушения.  
  - *Response*: массив `[{ "filePath":"File.cs", "line":42, "rule":"LongMethod", "message":"Метод слишком длинный", "severity":"High", "recommendation":"Разбить метод" }, ...]` (AnalysisResultDto).

# План миграций и порядок реализации  
1. **Создать базу данных и начальную миграцию EF Core**. Определить классы сущностей (Domain), настроить `DbContext`, выполнить `Add-Migration Initial` и `Update-Database`.  
2. **Реализовать базовые репозитории/сервисы Application** (интерфейсы `IProjectRepository`, `IAnalysisService` и т.п.), зависимые от доменных сущностей, но не от инфраструктуры.  
3. **Добавить контроллеры ASP.NET Core API**: `ProjectsController` (`POST /projects`, `GET /projects/{id}`), `AnalysesController` (`POST /projects/{id}/analyses`, `GET /analyses/{id}`, `GET /analyses/{id}/results`). Проверить работу эндпоинтов с реальной БД.  
4. **Настроить фоновые задачи**: создать `BackgroundService` для запуска анализов вне HTTP-потока. При `POST /projects/{id}/analyses` сохранять запись в таблице `Analysis` со статусом Pending, а затем асинхронно обрабатывать её в фоне и обновлять результаты.  
5. **Реализовать интерфейс `IAnalyzer` и подключить анализатор C#**. Добавить проект `Analyzers.CSharp`, определить общий контракт `IAnalyzer` и модель `AnalyzerResult`. Внедрить его в `BackgroundService`: анализ C#-проекта (с помощью Roslyn) и сохранение `AnalysisResult` в БД.  
6. **Проверить полный pipeline**: добавить в БД тестовый `Commit`, вызвать API, дождаться завершения анализа, убедиться, что результаты записаны и возвращаются через API.  
7. **Расширять функционал**: по очереди добавлять анализаторы для базы данных, SQL и безопасности (каждый – отдельный модуль, реализующий `IAnalyzer`).  
8. **Тестирование и деплой**: написать модульные тесты для сервисов, настроить Docker Compose (включая Postgres), CI/CD (GitHub Actions) для сборки и миграций.
