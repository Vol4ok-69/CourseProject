Правила проектирования и именования базы данных NetScope (PostgreSQL 17 / EF Core 10)

1. Соглашение об именовании идентификаторов (PostgreSQL):
   - Все имена таблиц и столбцов задаются в PascalCase и всегда заключаются в двойные кавычки ("Roles", "Users", "CreatedAt").
   - Таблицы именуются во множественном числе сущности:
     "Roles", "Users", "Projects", "Commits", "Analyses", "AnalysisResults".

2. Первичные ключи (Primary Keys):
   - Стандартный суррогатный первичный ключ: "Id" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY.

3. Внешние ключи (Foreign Keys):
   - Столбец внешнего ключа формируется как имя ссылаемой сущности в единственном числе + "Id":
     "RoleId", "UserId", "ProjectId", "CommitId", "AnalysisId".
     (Внимание: не имя таблицы во множественном числе, т.е. "RoleId", а не "RolesId").
   - Тип данных: INTEGER.
   - Обязательность: NOT NULL для обязательных связей, NULL для опциональных.
   - Ссылочная целостность: строгие внешние ключи с внешними ограничениями целостности (ON DELETE CASCADE, RESTRICT или SET NULL).

4. Нормализация (3НФ):
   - Схема базы данных спроектирована в третьей нормальной форме (3НФ):
     1НФ: атомарность атрибутов, отсутствие повторяющихся групп;
     2НФ: полная функциональная зависимость всех неключевых атрибутов от первичного ключа таблицы;
     3НФ: отсутствие транзитивных функциональных зависимостей (все неключевые атрибуты зависят непосредственно от первичного ключа).

5. Индексы и ограничения:
   - Первичные ключи автоматически индексируются СУБД.
   - Уникальные бизнес-индексы:
     * "Roles": UNIQUE ("Name")
     * "Users": UNIQUE ("Email")
     * "Projects": UNIQUE ("RepositoryUrl")
     * "Commits": UNIQUE ("Hash", "ProjectId")
   - Индексы внешних ключей:
     Все внешние ключи должны покрываться индексами для ускорения JOIN-соединений и каскадных операций (правило DB04, задачи TD-004 и TD-005).
