# Client Generation & Evolution Assessment

## 1. OpenAPI Version & Generator Compatibility
- `swagger.json` declares OpenAPI `3.0.4` (generated by `Swashbuckle.AspNetCore` `10.2.3`).
- Compatible with `.NET 10` (`NSwag`, `Kiota`, `Refit`/`Refitter`) and `TypeScript` (`openapi-typescript`, `orval`) — static assessment only (no generators executed).

## 2. Key Codegen Friction Points
1. **Missing `operationId` (`TD016-S5-006`):** All 26 operations lack `operationId`, causing noisy verb+path method names in NSwag/Refitter/orval.
2. **Global `Bearer` on `register`/`login` (`TD016-S5-005`):** Generated clients will treat anonymous auth endpoints as requiring a Bearer token unless overridden.
3. **`ProblemDetails` & `application/problem+json` (`TD016-S5-004`):** Typed error handlers cannot generate `code`, `traceId`, or `errors` or match `application/problem+json`.
4. **Nullable reference types (`TD016-S5-007`):** Missing `SupportNonNullableReferenceTypes()` makes non-null response fields optional in TypeScript/C#.
5. **Flattened `PagedResultDto<T>`:** Generates 3 separate classes (`UserDtoPagedResultDto`, `CommitDtoPagedResultDto`, `AnalysisDtoPagedResultDto`).

## 3. API Versioning & Evolution
- No API versioning is configured (`SwaggerDoc("v1")` is a label only; routes use `api/...`).
- Because 0 clients are implemented in `CourseProject.slnx` today, breaking changes have zero current client impact; however, before distributing independent CLI, Desktop (Tauri), and Telegram Bot repositories, introducing `/api/v1/...` or an explicit additive-only evolution policy is strongly recommended (`TD016-S5-013`).
