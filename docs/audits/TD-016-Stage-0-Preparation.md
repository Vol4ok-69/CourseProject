## 10. Ограничения среды

В ходе подготовки зафиксированы следующие условия и ограничения:

1. **Статический `swagger.json` в корне репозитория устарел:**
   Файл датирован `30.10.2026` и не содержит изменений, внесенных в API в ноябре 2026 г. (эндпоинты `/api/auth/me`, `/api/projects`, пагинация коммитов, новые поля DTO). На Stage 5 аудит API-контрактов должен опираться на динамическую генерацию Swagger из кода `Api.csproj`, а статический `swagger.json` должен рассматриваться как объект для актуализации.
2. **Отсутствие файла `Руководство_архитектора_ChatGPT.md`:**
   Документ не обнаружен в репозитории. Источником архитектурных правил выступают `AGENTS.md`, `docs/Технический регламент.md` и ADR-001.
3. **Безопасность данных при аудите PostgreSQL (Stage 3):**
   Локальный экземпляр PostgreSQL содержит пользовательские данные; любые диагностические запросы должны носить строго исследовательский характер (`read-only`), а нагрузочные замеры и тестирование сценариев `EXPLAIN ANALYZE` должны выполняться либо на временных схемах/БД, либо через механизмы Testcontainers / SQLite InMemory, исключая модификацию рабочей БД.
4. **Каталоги клиентов (`clients/Bot`, `clients/Cli`, `clients/Desktop`):**
   Каталоги физически существуют, но пусты. Аудит достаточности эндпоинтов (Stage 2) должен проводиться на основе формализованных сценариев использования клиентов из `API-Stabilization-Plan.md` и `TD-016`.
