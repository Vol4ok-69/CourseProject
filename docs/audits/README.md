# Реестр технических аудитов и аналитических материалов CourseProject

В данном реестре зафиксированы все ключевые аналитические материалы, технические регламенты, отчёты аудита архитектуры, базы данных, анализаторов и REST API проекта CourseProject.

## 1. Действующие архитектурные спецификации и регламенты

### 1.1. Технический регламент системы
- **Расположение:** [`docs/Технический регламент.md`](../Технический%20регламент.md)
- **Дата / Версия:** Октябрь–Ноябрь 2026 г. (.NET 10 / EF Core 10 / PostgreSQL 17)
- **Охват:** Архитектурный стиль (модульный монолит), границы слоев (`Domain`, `Application`, `Infrastructure`, `Api`), контракт анализаторов `IAnalyzer`, спецификация очереди задач в PostgreSQL, правила именования и организация клиентских приложений (`Cli`, `Desktop`, `Bot`).
- **Ключевой вывод:** Прямой доступ клиентов к БД запрещен; клиенты взаимодействуют исключительно через REST API; внешние брокеры (RabbitMQ, Kafka, Redis) исключены из рамок MVP; очередь задач реализуется на уровне PostgreSQL и `BackgroundService`.

### 1.2. Исполнительное резюме проекта
- **Расположение:** [`docs/Исполнительное резюме.md`](../Исполнительное%20резюме.md)
- **Дата / Версия:** Октябрь–Ноябрь 2026 г.
- **Охват:** Схема базы данных в 3НФ, DDL схемы миграций EF Core, описание сущностей (`Role`, `User`, `Project`, `Commit`, `Analysis`, `AnalysisResult`), доменные перечисления, каталог HTTP-эндпоинтов, модули анализаторов Roslyn и правила развертывания в Docker.

### 1.3. Правила проектирования базы данных
- **Расположение:** [`docs/Правила-базы-данных.txt`](../Правила-базы-данных.txt)
- **Охват:** Нормализация (3НФ), ссылочная целостность, первичные ключи (`"Id"` integer GENERATED BY DEFAULT AS IDENTITY), вторичные ключи (`"{Таблица}Id"` integer), строгое именование в `PascalCase` в кавычках.

### 1.4. Архитектурная схема системы
- **Расположение:** [`docs/Архитектура проекта.drawio`](../Архитектура%20проекта.drawio)

### 5.4. Архитектурное решение по изоляции анализатора БД и конвейера (ADR-001)
- **Расположение:** [`docs/architecture/database-analyzer-isolation.md`](../architecture/database-analyzer-isolation.md)
- **Архитектурный статус решения:** `ACCEPTED` (Архитектурное решение утверждено)
- **Статус реализации архитектурного решения:** Полностью реализовано (`IMPLEMENTATION_COMPLETE` / `VERIFIED`):
  - **Фактически реализованные компоненты:**
    1. *Статический анализ метаданных EF Core:* извлечение моделей через Roslyn C# AST без компиляции проектов и без динамической загрузки сборок (`src/Analyzers/Database/Roslyn/` и `Metadata/`).
    2. *Автономный Runner:* отдельный проект `NetScope.DatabaseAnalyzer.Runner` (`src/Analyzers/Database.Runner/`) с независимыми DTO и реализацией правил `DB01`–`DB05`.
    3. *JSON-контракт Backend–Runner:* независимый версионированный протокол обмена (`input.json` / `output.json`) через выделенный том `courseproject-exchange-data` с проверкой схем.
